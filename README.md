# IRONHOLLOW (doom_web)

> Браузерный шутер от первого лица в стиле Doom на **HTML, CSS и JavaScript**. Без сборки, без зависимостей, без внешних ассетов.

## О проекте

**doom_web** — учебный прототип статического веб-приложения, которое отображает псевдо-3D-мир методом *raycasting* (как в классических играх начала 90-х). Все текстуры и спрайты генерируются кодом при запуске, поэтому репозиторий состоит только из исходников.

Проект подходит для размещения в облаке как **статический сайт** (GitHub Pages, объектное хранилище, CDN): серверная часть не требуется.

**Текущие возможности:**

- два уровня («Подвал» и «Склад»), заданные в виде ASCII-карт;
- двери, цветные ключи (красный, синий, жёлтый), секретные стены;
- предметы: аптечки, броня, патроны, ключи;
- управление с клавиатуры, мыши (Pointer Lock) и геймпада;
- переключение разрешения 320×200 / 640×400, отладочный оверлей.

## Архитектура

Приложение полностью клиентское и работает в браузере. Модули подключаются обычными тегами `<script>` и обмениваются данными через общий объект `window.GAME`.

| Компонент | Файл | Назначение | Связь с другими компонентами |
|---|---|---|---|
| Конфигурация | `js/config.js` | Константы (скорость, FOV, разрешение), создаёт namespace `GAME` | Читается всеми модулями |
| Ввод | `js/input.js` | Клавиатура, мышь, геймпад | Источник команд для `player.js` и `game.js` |
| Данные уровней | `js/levels.js` | ASCII-карты уровней | Загружается в `map.js` |
| Карта | `js/map.js` | Сетка клеток, двери, секретные стены | Используется игроком и рендером |
| Предметы | `js/items.js` | Определения и подбор предметов | Меняет состояние игрока |
| Игрок | `js/player.js` | Позиция, здоровье, броня, ключи, движение | Опрашивает карту (коллизии) |
| Текстуры и спрайты | `js/textures.js`, `js/sprites.js` | Процедурная генерация изображений 64×64 | Потребляются рендером |
| Рендер | `js/renderer.js` | Raycasting стен, пол и потолок, спрайты, z-буфер | Рисует кадр на `<canvas>` |
| Главный цикл | `js/game.js` | Фиксированный шаг логики (60 Гц) и `requestAnimationFrame`, HUD, пауза | Связывает все модули |

Схема работы одного кадра:

```text
Input -> Player/Map/Items (обновление логики, шаг 1/60 с) -> Renderer (Canvas) -> HUD
```

## Структура репозитория

```text
doom_web/
├── index.html      # точка входа, canvas, HUD, порядок загрузки скриптов
├── style.css       # оформление страницы, HUD и экрана паузы
├── README.md       # документация проекта
└── js/
    ├── config.js   # настройки
    ├── input.js    # ввод
    ├── textures.js # процедурные текстуры
    ├── sprites.js  # процедурные спрайты
    ├── levels.js   # карты уровней
    ├── map.js      # логика карты и дверей
    ├── items.js    # предметы
    ├── player.js   # игрок
    ├── renderer.js # raycasting-рендер
    └── game.js     # главный цикл
```

## Технологии

| Технология | Применение |
|---|---|
| HTML5 `<canvas>` | Вывод кадра |
| JavaScript (ES6+, без модулей и сборщиков) | Вся логика игры |
| CSS3 | Оформление HUD и экрана паузы |
| Pointer Lock API, Gamepad API | Управление мышью и геймпадом |
| Git и GitHub | Хранение кода и совместная работа |

Серверной части, базы данных, Docker и внешних библиотек в проекте **нет**.

## Запуск

**Требования:** современный браузер (Chrome, Firefox, Edge, Safari) и Git. Для локального сервера понадобится Python 3 или Node.js (любой один вариант).

1. Клонировать репозиторий:

   ```bash
   git clone https://github.com/AllanZhantaykozha/doom_web.git
   cd doom_web
   ```

2. Запустить локальный статический сервер (один из вариантов):

   ```bash
   python3 -m http.server 8080
   ```

   ```bash
   npx serve .
   ```

3. Открыть в браузере [http://localhost:8080](http://localhost:8080) (для `npx serve` порт будет указан в консоли).
4. Нажать на экран, чтобы начать игру.

> Серверный API игре не нужен, поэтому `index.html` обычно можно открыть и напрямую из файловой системы. Локальный сервер рекомендуется для единообразного поведения браузера.

### Размещение в облаке (необязательно)

Так как проект состоит из статических файлов, его можно опубликовать через GitHub Pages: **Settings → Pages → Deploy from a branch → `main` / `(root)`**.

## Управление

| Действие | Клавиша |
|---|---|
| Движение | `W` `A` `S` `D` |
| Бег | `Shift` |
| Поворот | Мышь или стрелки |
| Открыть дверь / секрет | `E` или `Пробел` |
| Пауза | `Esc` |
| Отладка | `F3` |
| Разрешение 320×200 / 640×400 | `F4` |

## Работа с репозиторием

Изменения вносятся через отдельную ветку и Pull Request в `main`. Сообщения коммитов описывают суть изменения (например, `docs: добавить README.md с описанием архитектуры и запуском`). Секретные данные, токены и пароли в репозиторий не добавляются.
